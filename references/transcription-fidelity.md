# 密集摇滚的转录与保真复核

可演奏性启发式通过、文件可打开、MIDI 与 JSON 一致，均不能证明扒谱正确。在难度处理前保护原曲内容。

## 先定位损失层级

保留四份不覆盖的数据：原始检测输出、独立音乐观察、接受的原曲转录、最终改编。每份记录输入哈希、模型/参数、源轨、原音频时间和上一阶段哈希。接受或删除候选必须留原因；不得把最终事件反写成验收答案。

| 现象 | 区分方法 | 优先处理 |
|---|---|---|
| 指定 stem 没有主题，混音有 | 同窗、同增益比较 other 与其他候选源的绝对音高/瞬态 | 按乐句选源；弱 stem 不能证明休止 |
| 各候选源均被掩盖 | 复核混音、声像及重复段，排除检测失败 | 只对问题片段更换分离方法 |
| 候选有音，转录缺音 | 比较阶段间起音密度、音域、同音重击和八度运动 | 撤销无证据的 IOI、置信度、音域硬删除 |
| 转录正确，成谱错位 | 查弱起、拍号、三连音、延音及时间偏移 | 修正共同网格/记谱器，不逐轨拉伸 |
| 编配后主题变形 | 改编前后分别对照独立证据 | 先重排弦品/声部，简化必须可见 |

轨名只是模型估计类别。[Demucs](https://github.com/facebookresearch/demucs) 将六源模型列为实验性，钢琴分离尤其有限；[Basic Pitch](https://github.com/spotify/basic-pitch) 对单一乐器更有效。这些是排查方向，具体原因仍须用当前歌曲片段查证。

## 按乐句选源和保留起音

1. 预先声明全曲必查范围：开头主题、每个新段落首句、重复主题变奏、solo、拍号切换前后、结尾，覆盖六个谱表。未知观察也保留记录，不从分母消失。
2. 轨名与内容冲突时，用下面的 `route` 比较候选。它报告绝对 MIDI 音高频带能量，不按音级取模、不各自归一化、不叠加不同模型输出。频带能量只帮助选择下一次识音素材，不证明乐器身份或音符准确率。
3. 对选定备用轨重新做局部音符/起音检测，再回到混音、重复段复核。键盘两手可能保留在不同候选；合并按共同时间线去除跨源重复，不能复制成两名乐手。
4. 贝斯同时比较基频、八度、五度的谐波系列与邻音走向。单个谱峰或 pYIN 输出不足以定八度；禁止 `%12` 合并真实八度跳进或按阈值一律降八度。

```text
python scripts/transcription_evidence.py route --manifest work/separation/manifest.json --start 1.2 --duration 1.2 --pitches 88 90 --output work/source-route.json
python scripts/transcription_evidence.py retain --candidates work/raw-notes.json --range 21 108 --output work/retained-notes.json
python scripts/transcription_evidence.py attacks --features work/selected-source-features.npz --onsets work/observed-onsets.json --top-k 3 --output work/onset-pitch-candidates.json
```

候选每行为 `[开始秒,结束秒,绝对MIDI音高,置信度]`。`retain` 保留弱音、超范围音及密集同音，只标记起止均近似相同的同音高重复检测，保留原始索引。默认 12 ms 去重窗口不能改成八分音符间距；171 BPM 下十六分音符约 88 ms。它不是完整转录器。

`attacks` 输入 NPZ 的 `cqt_times`、`cqt_midi`、非负 `cqt[音高,时间]`，以及独立测得的起音秒列表。它比较起音后峰值与起音前基线，保存新增能量最高的多个候选；没有新增能量时报告证据不足。全部数组只解压一次。该方法能避免某些持续强音盖住新弱音，但不能保证在混音、颤音和泛音下总比其他方法准确，须与原始候选一起保留。

不要把参考谱的规则十六分音符网格直接当成真实起音测量。自由颤音、抢拍与尾音可能不逐格对应；先检测真实起音，再决定用颤音记号还是节奏化记谱。此案例在已指定高音区和网格的片段实验中，换轨恢复了高音内容，但逐窗最强音与起音新增能量两种简单方法都未达到逐音可靠。因此只能证明路由问题及后续模型局限，不能将其作为自动准确率提升的百分比。

## 共同网格与音乐表示

- 建立原音频秒与谱面拍的映射，允许音频在首小节中途开始；开头、中间、结尾须有实测锚点。总拍数一致不表示小节划分正确，还须验证重拍、和声转换和段落边界。
- 比较局部 4/4、3/4 等候选，不能用一个 2/4 掩盖连续 3/4。重复段用于检错，不能自动复制并抹掉变奏。
- 失真吉他先按整句区分旋律、和弦、切音，再核对瞬态/持续/声像；不要逐帧取最强音。主音不能仅因人声存在就删高音、弱拍音。
- 键盘两手分别考虑音域与复音。88 键钢琴上界是 C8（MIDI 108），不是 MIDI 88；超出编配舒适区先审查，不能从原曲转录中删除。
- 鼓件用音色、符头/位置和上下文区分；中频瞬态不全是军鼓。保留嗵鼓、开闭踩镲、ride/crash 与底鼓节奏。合并鼓双声部为单行起音和弦时，明确记录记谱时长的调整。
- 哑音、滑音、推弦、三连音、倚音不是噪声。先确认转换器能表达；不支持时列出范围，不能伪造成休止或普通有音高音符。

## 有参考谱时

先确认录音版本、调弦、实际响音、首拍及重复结构一致；参考谱本身也可能有错。TAB 与五线谱可交叉校音高，注意吉他/贝斯的移八度记谱。

PDF 自动读谱须检查每小节时值、横向同时点、符干/符杠、临时记号在小节内的延续、延音线、三连音、哑音、鼓双声部。页末提示拍号不是新小节。不确定项保留页码坐标，不能强行拉伸填满小节。

分别比较参考谱、原曲转录、改编谱的音高（含八度）、起音、时值、休止、拍号/弱起、声部归属、主题、和弦转位、奏法。允许改编另记，不算完全匹配。有参考谱的重建成绩不能冒充纯音频自动扒谱准确率。

## 独立音符证据契约

`fidelity_audit.py` 对比声明范围的音高、起音、时值，并检查来源及改编快照。证据结构：

```json
{"version":1,"provenance":{"kind":"reference_score","artifact_sha256":"实际64位十六进制哈希"},
 "required_phrases":[{"id":"theme-rh","part":"keys_rh","start":[2,0],"end":[2,4]}],
 "phrases":[{"id":"theme-rh","part":"keys_rh","start":[2,0],"end":[2,4],
 "source_kind":"reference_score","source_ref":"参考PDF第1页第2小节",
 "notes":[[0,88,0.25],[0.25,90,0.25]]}]}
```

示例音符仅演示格式，实际须完整记录声明范围，不能照抄。来源为 `reference_score` 或 `reviewed_mix_and_stems`；后者须记录具体观察/素材，不代表工具替人听过。裸 `stem_candidate` 输出仍待复核。空 notes 仅在 `silence_basis` 为 `reference_score` 或 `mix_and_stems` 时证明休止；未知留 `notes:null`，结果 incomplete。

```text
python scripts/fidelity_audit.py --events work/events.json --evidence work/fidelity-evidence.json --original-events work/transcription-before-arranging.json --authorized-changes work/arrangement-record.json --report work/fidelity-report.json
```

改编记录以 `original_events_sha256`、`arranged_events_sha256`（规范 JSON 哈希）、`authorization` 和 `reason` 绑定快照。授权不抹除参考差异。来源声明不是真实性证明，仍须审查生产链路，禁止给生成事件换一个“独立来源”标签。

证据还可列 `dead_strokes:[[相对拍,弦号数组,时长]]` 和 `grace_groups:[[相对拍,倚音数组]]`，防止删掉哑音/倚音后仍以音高匹配通过。仅鼓可指定 `duration_policy:"attacks_only"`，用于保留起音与鼓件但重新整理记谱时值；报告明确标出此范围，不适用于有音高延音。

无法原样表达的推弦等细节写入 `known_differences`；即使列明的音符检查通过，`reference_match` 仍为 false。这不允许将已知错音移入备注绕过检查，音高/起音/持续差异仍按主检查失败处理。

## 保留参考内容的复核稿

动作模型不覆盖连续推弦、滑音和全部和弦连接。不能为了让它通过而先改写正确音符。若用户要求参考谱重建而模型拒绝既定弦品，可用 `build --notation-only` 生成内容复核稿：每个弦乐实音必须已有明确 TAB，弦品/音高和节奏验证仍执行，动作状态保持 incomplete。保留正常动作检查的失败报告，禁止用此模式宣称高可演奏性已经验证。

复核稿导出使用 `--review-draft "具体未验证范围和改编限制"`，同时必须提供绑定的 notation-only 报告、通过的独立音符证据与节奏证据。它不放行 needs_repair 动作报告，也不放行谱面结构错误；manifest 的 release_status 为 review_draft，交付时必须说明演奏验证尚未完成。此分支用于如实提供可编辑复核材料，不替代普通音频任务的正式质量门槛。

## 本次失败留下的回归案例

《雑踏、僕らの街》的开头高音钢琴主题主要保留在 other，而非 piano；随后八分音符去重和固定音域筛选又放大了损失。参考为 139 小节、多段 3/4 与 4/4 交替；旧谱虽也是 520 拍，却用 131 小节和两处 2/4 表示。还有哑音缺失、低音八度/五度混淆与循环验收。修复应依次检查来源路由、候选保留、共同网格、奏法表达及独立复核，不能只增加分轨次数或放宽评分阈值。
